1. Что такое .Net Framework и из чего он состоит?
.Net Framework - платформа от Microsoft, служащая основой для создания 
и запуска компьютерных приложений и игр на Windows
из чего он состоит - CLR, FCL, Технологии создания приложений

CLR(Common Language Runtime) - Общеязыковая среда выполнения. Это «сердце» платформы, виртуальная машина, 
которая управляет работой запущенного приложения.

FCL(Framework Class Library) - Библиотека классов платформы. Это колоссальный набор готового, 
протестированного кода, который программисты используют как строительные блоки.

Технологии создания приложений - Набор готовых каркасов для создания разных типов программ.

2. Что такое CLR, FCL/BCL, CLI, IL?
CLR(Common Language Runtime) - Общеязыковая среда выполнения. Это «сердце» платформы, виртуальная машина, 
которая управляет работой запущенного приложения.

FCL(Framework Class Library) - Библиотека классов платформы. Это колоссальный набор готового, 
протестированного кода, который программисты используют как строительные блоки.
BCL (Base Class Library) — Базовая библиотека классов. Это фундамент фундамента. Сюда входят только те самые элементарные типы данных и функции, без которых в принципе невозможно написать ни одну программу, даже самую простую текстовую утилиту.

CLI(Common Language Infrastructure) - это «свод законов и правил», который описывает, как должна быть устроена виртуальная машина, чтобы на ней можно было запускать программы, написанные на разных языках программирования (C#, VB.NET, F#, C++/CLI), и чтобы они идеально понимали друг друга.
Как соотносятся CLI и то, что мы учили раньше?
Связь между ними прямая: 
CLI — это теория (чертеж), а .NET Framework — это практика (реализация).CLI (Стандарт) говорит: «Внутри платформы должна быть среда выполнения, управляющая памятью, и базовая библиотека классов».
CLR — это то, как Microsoft реализовала эту среду выполнения в железе и коде для Windows.
BCL — это то, как Microsoft реализовала базовую библиотеку по правилам стандарта.

3. Пояснить работу JIT-компилятора?
Just-In-Time, «точно в срок»
это технология, которая превращает код программы 
в быстрые машинные инструкции прямо во время работы этой программы.
  Код сначала переводится в промежуточный байт-код, а при запуске JIT превращает его в машинный.
  В свою очередь это дает скорость и кроссплатформенность
1. Компиляция в байт-код (Roslyn): Компилятор C# переводит исходный код в промежуточный язык — IL (Intermediate Language) (или MSIL/CIL) — и упаковывает его в .dll или .exe файл. Этот код одинаков для Windows, Linux и macOS.
2.Запуск программы (CLR): Когда пользователь запускает этот файл, операционная система поднимает среду CLR.
3.Работа JIT: Когда управление доходит до какого-либо метода, JIT-компилятор подхватывает его IL-код, транслирует в машинный код (ассемблер x64 или ARM) конкретного процессора и выполняет.
Главная особенность C#: Многоуровневый JIT (Tiered Compilation)В современных версиях .NET (начиная с .NET Core 3.0 и заканчивая современными .NET 8/9/10) используется технология Tiered Compilation. Она решает вечную проблему: компилировать код качественно (но долго) или быстро (но с плохой оптимизацией)?.NET делает и то, и другое, используя два основных уровня (Tiers):
Уровень 0 (Tier 0 — Quick JIT)Когда метод вызывается впервые, JIT компилирует его максимально быстро. Он практически не применяет сложные оптимизации.Цель: Минимизировать время запуска приложения (Startup time). Пользователь не должен ждать, пока JIT «думает» над кодом.На этом же уровне CLR ставит на метод невидимый счетчик вызовов.Уровень 1 (Tier 1 — High Optimization)Если метод вызывается очень часто (становится «горячим»), счетчик срабатывает. CLR понимает: на этот метод тратится много времени, его нужно ускорить.В фоновом потоке запускается процесс перекомпиляции.JIT применяет самые тяжелые и умные оптимизации (инлайнинг, векторизацию, развертку циклов).Готовый высокоэффективный машинный код подменяет старый Tier 0 код в памяти.

4. Что такое CTS (Common Type System)?
формальная спецификация (стандарт), которая входит в состав среды .NET (выступая частью CLR) и строго определяет, как типы данных должны объявляться, представляться в памяти и взаимодействовать друг с другом.

5. Какие аспекты поведения определяет тип System.Object?
Класс System.Object (в C# для него есть псевдоним object) является корнем всей иерархии типов в .NET [CTS]. Абсолютно любой тип — будь то класс, структура, массив или перечисление — прямо или косвенно наследуется от него.Поскольку он стоит во главе всего, System.Object определяет фундаментальные аспекты поведения любого объекта в среде .NET. Эти аспекты можно разделить на две категории: базовые методы (доступные для переопределения) и системные механизмы управления.
  1. Контракт идентичности и сравнения (Identity & Equality)
System.Object задает правила, по которым среда .NET понимает, равны ли два объекта между собой. За это отвечают два метода:Equals(object obj)Поведение по умолчанию: Для ссылочных типов проверяет ссылочное равенство (указывают ли две переменные на один и тот же адрес в куче).Переопределение: Разработчики могут переопределить этот метод, чтобы сравнивать объекты по значению (например, два пользователя равны, если у них совпадают ID). Встроенный тип string и все значимые типы (ValueType) уже переопределяют его для сравнения содержимого.ReferenceEquals(object objA, object objB) (статический метод)Поведение: Жестко проверяет, указывают ли ссылки на одну и ту же ячейку памяти. Его нельзя переопределить, что гарантирует возможность всегда проверить идентичность ссылок, даже если обычный Equals был изменен.2. Уникальное хэширование (Hashing)GetHashCode()Поведение по умолчанию: Возвращает суррогатный числовой идентификатор объекта (хэш-код), который генерируется средой CLR на основе адреса объекта в памяти или внутреннего индекса.Зачем это нужно: Этот метод критически важен для работы быстрых коллекций, таких как Dictionary<TKey, TValue> или HashSet<T>. Если вы переопределяете метод Equals, CTS строго требует переопределить и GetHashCode, чтобы у одинаковых (по логике Equals) объектов были равные хэш-коды.3. Текстовое представление (String Representation)ToString()Поведение по умолчанию: Возвращает полное имя типа объекта (например, MyNamespace.User).Переопределение: Этот метод переопределяют чаще всего, чтобы возвращать понятную человеку информацию об объекте (например, для вывода в консоль, логирования или дебага: вместо имени класса возвращается "Иван Иванов (ID: 42)").4. Рефлексия и метаданные (Type Inspection)GetType()Поведение: Возвращает объект System.Type, который содержит полную информацию о типе во время выполнения программы (имя, методы, свойства, базовый класс и т.д.).Особенность: Этот метод нельзя переопределить (он не виртуальный). Это гарантирует безопасность CTS: объект никогда не сможет «скрыть» или подделать свой реальный тип от системы рефлексии или сборщика мусора.
  Внутреннее поведение: управление памятью. 
Помимо методов, System.Object несет в себе скрытые для обычного кода, но фундаментальные для CLR аспекты поведения:Синхронизация потоков (SyncBlock Index): Каждый объект в куче .NET, благодаря наследованию от Object, имеет невидимый заголовок, содержащий индекс блока синхронизации. Именно это позволяет использовать абсолютно любой объект в конструкции lock(obj) для многопоточной синхронизации.Жизненный цикл и Сборка мусора: System.Object определяет защищенный метод Finalize() (в C# пишется как деструктор ~MyClass()). Сборщик мусора вызывает его перед уничтожением объекта, если объекту нужно освободить неуправляемые ресурсы (например, дескрипторы файлов или сетевые соединения).Хотите посмотреть, как правильно переопределять Equals и GetHashCode, чтобы объект корректно работал в коллекциях вроде Dictionary, или вас интересует тема рефлексии через метод GetType()?
  
6. Что находится в mscorlib dll?
mscorlib.dll (расшифровывается как Microsoft Microsoft Common Object Runtime Library) — фундаментальная базовая библиотека классов (Base Class Library — BCL) классического .NET Framework. Это единственная сборка, которую среда выполнения (CLR) обязана загрузить в каждый управляемый процесс, так как без нее работа программы невозможна.
!💡! Важное замечание про современный .NET (Core / .NET 5+):Начиная с .NET Core и в современных версиях .NET (включая современные .NET 8 и .NET 9) файл mscorlib.dll больше не является основным хранилищем. Весь его код переехал в другую библиотеку — System.Private.CoreLib.dll. Тем не менее, содержимое и концептуальная роль у них одинаковы.
 Что конкретно находится внутри mscorlib.dll? 
Поскольку эта DLL тесно связана с самой виртуальной машиной (CLR), в ней находятся типы, необходимые для работы синтаксиса языка, базовых операций ввода-вывода и системных механизмов.
 
7. Что такое «сборка»? Из чего состоит сборка .NET?
сборка это основной строительный блок приложений, который представляет собой логическую единицу, содержащую скомпилированный код, и физически выражается в виде файлов с расширением .dll (библиотека кодовых элементов) или .exe (исполняемый файл).
Сборка .NET состоит из 4 основных элементов:
Манифест (Manifest) — «паспорт» сборки. Содержит имя, версию, список файлов и зависимости от других сборок. Метаданные (Metadata) — описание всех типов данных: классов, интерфейсов, их методов, свойств и параметров.CIL-код (Common Intermediate Language) — промежуточный байт-код программы, в который компилируется исходный код (например, C#).Ресурсы (Resources) — встроенные в сборку файлы: изображения, иконки, звуки и строки локализации.Все эти элементы обычно упакованы в один файл .dll или .exe.

8. Какие виды сборок существуют?
Закрытые и открытые.

9. Что такое assembly manifest?
внутренний блок метаданных, который выполняет роль «паспорта» сборки. Без него .NET-приложение не сможет запуститься, так как среда выполнения (CLR) не поймет, что это за файл и как с ним работать.

10.Что такое GAC?
GAC (Global Assembly Cache / Глобальный кэш сборок) — это централизованное общесистемное хранилище в Windows, которое использовалось в классической платформе .NET Framework для размещения общих (разделяемых) сборок.
Если говорить простыми словами, это специальная папка на компьютере, куда устанавливались библиотеки (.dll), которые должны быть доступны сразу всем .NET-приложениям в системе.
Современный статус: Что с GAC в новом .NET (Core / 5+)?В современном .NET (Core, .NET 5, 6, 7, 8, 9) технологии GAC больше нет.Создатели платформы отказались от глобального кэша сборок в пользу модульности и концепции XCOPY-развертывания (когда все файлы приложения лежат в одной папке). Вместо GAC сегодня используются:Папка shared в директории установки .NET — там лежат только официальные runtime-библиотеки от Microsoft.Локальный кэш NuGet-пакетов (в папке пользователя .nuget/packages) — используется на этапе разработки.Self-contained deployment — режим публикации приложения, при котором вообще все необходимые .dll (включая саму платформу .NET) упаковываются прямо в папку с вашей программой, делая её полностью независимой от системы.

11.Чем managed code отличается от unmanaged code?
Managed code (управляемый код) и unmanaged code (неуправляемый код) — это два принципиально разных подхода к выполнению программ, которые различаются тем, кто управляет памятью и безопасностью приложения: специальная виртуальная машина или напрямую операционная система.
 Managed код исполняется под полным контролем среды выполнения CLR (.NET), 
 Unmanaged код компилируется напрямую в машинные инструкции процессора и работает с железом без посредников.
  Могут ли они работать вместе? Да, могут. В .NET для этого существует механизм под названием Interop (P/Invoke). Например, если вашей C#-программе нужно вызвать старую, но очень быструю библиотеку, написанную на C++, или обратиться к низкоуровневым функциям Windows API (Win32), .NET позволяет временно «выйти» из управляемой среды, выполнить неуправляемый код и вернуться обратно.

13.Варианты использования директивы using( using Directive ) в C#.
1. Подключение пространства имен (Using namespace directive)Это самый частый сценарий. Директива указывает компилятору, из какого пространства имен брать классы, чтобы не писать их полные пути каждый раз.csharp// Без using пришлось бы писать: System.Console.WriteLine();
using System; 

class Program {
    static void Main() {
        Console.WriteLine("Привет!"); // Доступно напрямую благодаря using System;
    }
}

2. Создание псевдонима (Using alias directive)Используется, когда нужно переименовать длинный класс/пространство имен или решить конфликт, если в двух разных библиотеках оказались классы с одинаковым именем.csharpusing ProjectGeometry = ComplexEnterpriseApplication.Backend.Math.Geometry;
using LegacyTimer = System.Timers.Timer;
using NewTimer = System.Threading.Timer;

class Program {
    static void Main() {
        // Используем короткий и понятный псевдоним вместо огромного пути
        ProjectGeometry.Point point = new ProjectGeometry.Point(); 
    }
}

3. Подключение статических членов класса (Using static directive)Появилась в C# 6. Позволяет импортировать не пространство имен, а конкретный статический класс. После этого все его статические методы и свойства можно вызывать напрямую, вообще без указания имени класса.csharpusing static System.Math; // Импортируем математический класс
using static System.Console;

class Program {
    static void Main() {
        WriteLine(Sqrt(16)); // Вместо Console.WriteLine(Math.Sqrt(16));
    }
}

4. Глобальный using (Global using directive)Появилась в C# 10. Если добавить слово global перед директивой, то указанное пространство имен станет доступно во всех файлах проекта автоматически. Обычно такие директивы выносят в отдельный файл (например, Usings.cs).csharp// В файле Usings.cs
global using System;
global using System.Collections.Generic;
global using System.Linq;

// Теперь в ЛЮБОМ другом файле проекта писать "using System;" больше не нужно!

14.Как связаны между собой сборки и пространства имен?
Никак, они просто работают параллельно. Одно пространство имен может быть во многих сборках одновременно ровно так же как и одна сборка может содержать в себе сколь угодно много разных пространств имен.

15.Что такое примитивные типы данных? Перечислите их.
Примитивные типы данных в .NET — это самые простые, базовые типы данных, которые распознаются напрямую компилятором языка и среды выполнения (CLR) и хранятся в стеке.Они служат фундаментом для создания любых других сложных структур и классов. Главная их особенность в C# — для каждого примитивного типа есть специальное ключевое слово (псевдоним), которое синтаксически подсвечивается в коде, но под капотом полностью соответствует определенной системной структуре из пространства имен System.

Примитивные типы делятся на четыре логические группы:
1. Целочисленные типы (Integers)
sbyte (System.SByte) — 8-битное целое со знаком (от -128 до 127).
byte (System.Byte) — 8-битное целое без знака (от 0 до 255).
short (System.Int16) — 16-битное целое со знаком.ushort (System.UInt16) — 16-битное целое без знака.
int (System.Int32) — 32-битное целое со знаком (самый используемый тип для чисел).
uint (System.UInt32) — 32-битное целое без знака.
long (System.Int64) — 64-битное целое со знаком (для очень больших чисел).
ulong (System.UInt64) — 64-битное целое без знака.
nint / nuint (System.IntPtr / System.UIntPtr) — целые числа, размер которых зависит от разрядности операционной системы (32 или 64 бита).
2. Типы с плавающей точкой (Дробные)
float (System.Single) — 32-битное вещественное число (одинарная точность).
double (System.Double) — 64-битное вещественное число (двойная точность, стандарт для математических расчетов).
3. Логический типbool (System.Boolean) — принимает только два значения: true (истина) или false (ложь).
4. Символьный типchar (System.Char) — один 16-битный символ в кодировке Unicode (например, 'A' или '7').

16.Что такое ссылочные типы? Какие типы относятся к ним?
Ссылочные типы (Reference Types) в .NET — это типы данных, объекты которых хранятся в управляемой куче (Managed Heap), а в переменной хранится лишь ссылка (адрес памяти) на это место.
 Все ссылочные типы в .NET можно разделить на четыре основные группы:
1. Классы (Classes)object (System.Object) — базовый предок абсолютно всех типов в .NET.
string (System.String) — текстовые строки. 
Важно: хотя строки являются ссылочным типом, они неизменяемы (immutable) и ведут себя в коде похоже на значимые типы.
Пользовательские классы — любые классы, которые вы создаете сами с помощью ключевого слова class (например, class User, class Order).
Встроенные системные классы .NET (например, List<T>, StringBuilder, HttpClient).
2. Интерфейсы (Interfaces)Переменная типа интерфейса (например, IEnumerable, IDisposable) всегда хранит ссылку на объект класса, который этот интерфейс реализует.

4. Делегаты (Delegates)Типы, которые хранят ссылки на методы (например, Action, Func<T>, delegate).

27.Какие методы есть у типа String?
1. Поиск и проверка содержимого
Эти методы помогают узнать, что находится внутри строки, или найти индекс нужного символа.
Contains(value) — возвращает true, если подстрока есть внутри строки.
StartsWith(value) / EndsWith(value) — проверяют, начинается или заканчивается ли строка на указанный текст.
IndexOf(value) / LastIndexOf(value) — возвращают индекс первого или последнего вхождения символа/подстроки. Если ничего не найдено, возвращают -1.
2. Изменение и трансформация (возвращают НОВУЮ строку)
Replace(oldValue, newValue) — заменяет все вхождения одного текста/символа на другой.
ToLower() / ToUpper() — переводят всю строку в нижний (маленькие буквы) или верхний (ЗАГЛАВНЫЕ) регистр.
Trim() / TrimStart() / TrimEnd() — удаляют все пробелы (и переносы строк) с обоих концов строки, либо только в начале/конце.
Insert(startIndex, value) — вставляет текст в указанную позицию.
Remove(startIndex, count) — удаляет указанное количество символов, начиная с заданной позиции.
3. Разделение, соединение и обрезкаSplit(separator) — разрезает строку на массив подстрок по указанному разделителю (например, по запятой или пробелу).
Substring(startIndex, length) — вырезает из строки кусочек заданной длины, начиная с указанного индекса.
string.Join(separator, array) (статический) — собирает массив элементов обратно в одну строку, проставляя между ними разделитель.
4. Статические методы для проверки на «пустоту»
Эти методы вызываются не у конкретной переменной, а у самого класса string. Они заменяют долгие проверки в коде.
string.IsNullOrEmpty(str) — возвращает true, если строка равна null или пустая ("").
string.IsNullOrWhiteSpace(str) — более мощный метод. Возвращает true, если строка равна null, пустая, либо состоит только из пробелов, знаков табуляции или переносов строк.

36.Что такое кортеж? Для чего и как он используется?
Кортеж - легковесная структура данных, которая позволяет объединить несколько элементов (возможно, разных типов) в один объект без создания полноценного класса или структуры [].
Если вам нужно временно сгруппировать две-три переменные (например, имя человека и его возраст), вам не обязательно создавать ради этого отдельный класс class User. Можно использовать кортеж прямо на лету.
Главный сценарий использования кортежей — возврат нескольких значений из метода.

Область видимости локальной функции строго ограничена блоком кода (фигурными скобками {}), внутри которого она объявлена [].
